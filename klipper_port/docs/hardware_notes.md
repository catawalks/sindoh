# DP200 UPC hardware notes (verified 2026-10-17)

## Measured on the printer (2026-10-17, serial console + WiFi)

| Result | How |
|---|---|
| **XENA Timer1 (0x08001144) = 32-bit one-shot down-counter at 395.76–395.85 MHz** (2 × 198 MHz dithered bus clock). Loaded with 0xffffffff it runs ~10.8 s and stops at 0; reloading before 0x40000000 gives a continuous count. PerfMon timers, Timer0/2/3 and the Phase/encoder registers do not run. | probe firmware, rate vs Linux CLOCK_MONOTONIC |
| **Thumb works on both cores.** Each core's CP15 main ID is Marvell 0x56, ARMv5TE-class, part 0x101: FM `0x56051012`, IO `0x56151012`. Control register 0x1f74. Start CPSR 0x600000d3. | probe |
| **Executing code from DTCM stalls the core** (no prefetch abort is raised). The first probe also froze the whole SoC, Linux included. Never fetch from DTCM, and don't probe unmapped addresses. | probe steps 3/4 |
| DTCM physical base **0xf9280000** (second `marvell-upc` resource `f9210000-f92bffff` + 0x70000). `/proc/iomem` also lists `f9200000-f920ffff`. | upctool nonce check |
| Stock DTCM status words (0x9888 block) stay zero until Linux sends command 0x1e. The tables at 0x0 and the checksum at 0x91d0 are live. | upctool dump |
| ADC sel 0 = nozzle, sel 1 = bed. They match the stock firmware's own conversion: raw 891 → stock 64.6 °C, raw 692 → stock 44.2 °C. Readings are very stable (±1 count). | probe + DTCM lookup tables |
| Inputs at rest: XIRD = 0x10140000; XIRD1 bit 10 (xena42, X home) = 1; xena43/44/46 = 0. Endstop polarity still to be mapped by pressing the switches. | probe, Klipper endstop_query |
| **Klipper firmware runs on both cores.** Over WiFi and the TCP bridge, the following work: identify, get_config, clock (FM 396.6 / IO 394.7 MHz over 8 s, ±1% from RTT jitter), endstop_query_state, analog_in (nozzle raw ≈ 973, bed raw ≈ 771 while cooling) and the `reset` command. RTT is 50–130 ms over WiFi. | tools/khost.py, kreset.py |
| **Motion works under Klipper.** On the extruder (engine 3), 460 steps forward over 1 s, a 0.5 s pause and 460 back turned the motor smoothly both ways (observed at the printer). The firmware's position returned to 0 with no shutdown. This confirms on real hardware the one-engine-pulse-per-step pin, the DIR bit (+0x44 bit 4), the driver enable (CFG bit 0 = 0) and the hardware-PWM REF current (block 0x1f at 75 %). | tools/ktest_motion.py |
| **Axis directions** (Klipper DIR value → motion observed): X: 0 = carriage left (so 1 = right = +X, towards the MAX home). Y: 1 = bed forward. | **CORRECTED: X endstop xena42 is 1 = triggered**, like Y and Z. The stock homing code (FM cmds 0x20-0x24) approaches until the bit reads 1, then backs off until it reads 0. At the hand test the carriage was parked on the switch (stock parks at X home), so it read 1 at rest and 0 when moved away. Klipper: `xena42`. **Filament sensor = xena46 (XIRD1 bit 14): 0 = filament present, 1 = empty** (stock status bit 3, IF_FILA_INSERTED). **Extruder: DIR 1 = retract, DIR 0 = feed**, so Klipper uses `dir_pin: !smot_dir3`. **Y endstop xena43 (XIRD1 bit 11) is active-high**: 0 when free, 1 when the bed is moved by hand into the switch (after raising the bed 20 mm). | **Fans (IO core, static on, observed):** pwm1 = extruder/hotend heatsink fan, pwm2 = part-cooling fan, pwm3 = nothing connected, pwm4 = rear case exhaust fan with mesh filter. | **Nozzle heater works under Klipper** (pwm5, soft PWM 0.1 s cycle, 30 % cap): 27 → 60 °C in ~33 s (~1.1 °C/s at 30 %), P-only overshoot to 62.7 °C. No safety layer needed to act. What the Klipper port relies on, with where each fact comes from. "Static"
means read from code; "emulated" means observed by running the stock

## Linux side (upc.ko, kernel 3.2)

| Fact | Evidence |
|---|---|
| ioctl `0xc0017522` → `CPUSoftReset = 0` (both cores held); `0xc0017521` → `= 1` (run). One global register: the two cores cannot be reset independently. | upc_ioctl → upc_soft_reset(0/1); stock reset_UPCs / bootup_UPCs |
| `0x7523` selects ITCM for the next write(). `0xc0047524` selects DTCM and takes the offset **by value**. The file position is per open file and there is no lseek, so reopen for each transfer (as the stock app does). | upc_ioctl, upc_write, writeFD0_DTCM |
| ITCM writes are limited to 0x4000 bytes per core. DTCM read/write through the driver is limited to 0x20000; the cores see 0x40000. | upc_read / upc_write bounds |
| **The mailbox-write ioctl `0xc0087530` blocks**: for box 0 or 5 it waits (interruptibly) for the GPStatus-bit-0 IRQ, and for box 1 the bit-1 IRQ. It holds the driver's global mutex while waiting. | upc_ioctl → wait_for_completion_interruptible; upc_platform_irq clears the bit and calls complete() |
| DTCM = `upc_data_array[1].base + 0x70000`; XENA registers = `upc_data_array[0].base + 0x8000`. Physical bases come from the board file, so upctool finds DTCM by writing a nonce through the driver and searching for it via `/dev/mem`. | upc_read_dtcm, upc_get_regbase_addr |
| `CONFIG_STRICT_DEVMEM` is not set, so `/dev/mem` can map DTCM and peripherals. | IKCONFIG (docs/kernel/vendor_3.2.0-g67a8e16.config) |
| **HZ=100 and no `CONFIG_HIGH_RES_TIMERS`**: every sleep or poll lasts at least 10 ms. The bridge spins with sched_yield for 5 ms after traffic to cut latency. | IKCONFIG |
| The CPU is ARMv7 with **VFPv3-D16**. Host binaries must not use d16–d31 or NEON (gcc: `-mfpu=vfpv3-d16`). A Cortex-A9 target produced 510 illegal register uses. | main ELF attributes; tools/vfpscan.py |

## UPC cores

| Fact | Evidence |
|---|---|
| Vectors at 0: reset → 0x2c, IRQ → 0x18. The stock code runs IRQ-driven. FM stacks are at 0x0403_8000–0x0404_0000 and IO stacks at 0x0403_0000–0x0403_8000; DTCM is shared by both cores. | disassembly of fm.bin / io.bin |
| FM: `IRQEnableFM[0] = 0x240`. Bit 9 = command (Linux wrote mailbox 5); the handler acks with `IntClearFM = 0x200` and `GPStatus |= 1`. FIQ bit 4 = emergency stop, and `Mailbox0 == 0x18184444` halts the core. | fm 0xc00 init, 0x1178 IRQ, 0xb84 FIQ |
| IO: `IRQEnableIO = 0x21` (bit 0 Timer0, bit 5 command). Every tick re-writes `Timer0 = 200 000 000`, so Timer0 is a one-shot countdown. **Nothing in the stock code reads a free-running counter.** | io 0x2074 init, emulated ticks |
| The microcode is pure ARM. Thumb support, DTCM execution and the real ITCM size are unknown; the probe tests all three. | static |

## Peripherals

| Fact | Evidence |
|---|---|
| **dec_pwm**: register block N at `0xf9304000 + 0x100·N` with global enable bit **N−1** at `+0`. `+8` = high ticks, `+0xc` = low ticks, ctrl bit 0 = PWM running, **ctrl bit 2 = static output level while not running** (the old note "bit2 = output enable" was wrong). 0% and 100% use the static level. | emulated IO init; io_026c / io_0338 |
| Blocks: 1–4 fans (period 100), 5 nozzle heater (1000), 0x18 bed heater (1000), 0x1b/0x1d/0x1e/0x1f motor REF X/Y/Z/E (200), 6 clutch, 8 solenoid. | emulated init + earlier session |
| **Stepper engines** `0xf8150000 + 0x1000·n`: a move is `+0x8c=0x100` (clear), `+0x50=1`, `+0x58` = ticks per edge, `+0x44` = 0x33224 / 0x33234 (bit 4 = direction), `+0x5c = (edges<<16)|mode` with edges = 2·steps, `+0x60=1` start; `+0x04=0x100` aborts. The 200 MHz clock is confirmed independently: 120000 ticks per edge = 10.4 mm/s at 80 steps/mm, which matches the stock X homing speed. | emulated FM commands 0x0c, 0x24, 0x2f |
| **ADC**: the FIFO holds 10 samples (10-bit, masked 0x3fff) at `0xf930a180`. Mux word `0x10100 | sel` goes to `0x200..0x220`, and `0x224 = word & ~0x10000`; sel 0 = nozzle, 1 = bed. Stock processing: scale ×2048/1023, drop min and max, average 8. The draft thermistor tables (code/2048) therefore equal raw/1023, so the port reports raw counts with `ADC_MAX = 1023`. | io_0680, io_2718, io_2944, io_08e0 |
| Home sensors X/Y/Z = XIRD1 bits 10/11/12 (pins 42/43/44). Polarity TBC. | earlier session; probe reports live bits |

## Open items for `upctool probe`

1. Which counter is free-running, its direction and frequency (sets `CONFIG_CLOCK_FREQ`, `UPC_TIMER_ADDR`, `UPC_TIMER_DOWN` and `UPC_TIMER_START`).
2. Thumb support (the Klipper images need Thumb to fit in 16 KiB).
3. Whether a single-pulse engine move (`edges = 2`) really produces one STEP pulse, and how long the engine needs between moves.
4. Endstop polarity, ADC values at room temperature, and how quickly the ADC FIFO refreshes after a mux change (`UPC_ADC_SETTLE_US`).
5. Which PWM blocks drive which fan, and the PWM clock (hardware-PWM `cycle_time` is currently ignored).
