# Sindoh 2X: the stock machine (first look)

**Source:** the owner's 3DWOX 2X, surveyed on 2026-11-28 with the survey
stick (v1.2, read-only) and a few reads over the stick's remote shell.
Nothing on the printer was changed. The survey text and the copied
scripts stay on the owner's PC (`2x_files/`); they are Sindoh's and are
not published. Inferences are marked "(our reading)". The board itself
and its factory SD card are described in [prime_sd.md](prime_sd.md);
the 1X, which this page compares against, in [1x.md](1x.md).

## Identity

| | 2X | 1X (for comparison) |
|---|---|---|
| Firmware | `PRIME_210419_2` | `ROD1X_200916_2` |
| `RODIN_SUB` | `P` | |
| Board name (`/sys/kernel/board_name`) | `TOC` | `1X_r1` |
| Device tree model | "mv6270 TurnOn Card-Rev C" (`marvell,mv6270-toc`) | `mv6270-1X` |
| TLI | `3D2XAQ` | `3D1XAH` |
| Kernel | 4.2.8, built 2020-11-24 | 4.2.8, built 2019-01-24 |
| Update folder on a stick | `_update_rodin_prime` | `_update_rodin_1x` |
| RAM | 1 GB | 1 GB |

Stock's own scripts call this hardware **"Prime_r1"**, and the eMMC
board (the 1X's kind) **"Prime_r2"**: `powerkeyd.sh` and
`screen_pwroff.sh` branch on the board name, and anything that is not
`Prime_r2` takes the r1 path. This printer takes the r1 path.

## Storage and boot: a NAND machine

The 2X boots like the DP200 family, not like the 1X.

- **NAND**, eight partitions: `miniloader` (1 MB), `r4` (1 MB),
  `u-boot-env` (1 MB), `boot-logo` (2 MB), `u-boot` (1 MB), `kernel`
  (5 MB), `dtb` (512 KB), `filesystem` (the rest, 500 MB).
- **Root** is UBIFS on `filesystem` (`root=ubi0:filesystem`), mounted
  read-write with `sync`. It is **90 % full: 42 MB free** of 447 MB.
  5 bad blocks, highest erase count 944.
- **U-Boot:** `bootcmd=run nandboot`; the environment is in NAND
  (`/dev/mtd2`). It also has a `load_sdcard` line (`mmc dev 2`, kernel
  and `mv6270-toc.dtb` from partition 2 of a card).
- **No `/userdata`, no `/systemdata`.** The 1X's install places do not
  exist here. `/recovery` (177 MB: `rootfs.tar.bz2`, `app.tar.bz2`,
  `recovery.check.sh`) is a folder inside the NAND root.
- **The factory SD card** (8 GB "SL08G", 2018) is in its socket, as
  `mmcblk0` with four partitions (3 MB, 302 MB, 512 MB, 6.6 GB), and
  is **not mounted** in normal running. Partition 2 is an ext
  filesystem last mounted as `/` in January 2018 (the factory image,
  see prime_sd.md); stock's `recovery.check.sh` and `sd_crypt_util.sh`
  refer to partitions 2 and 3.
- **Power-off (r1 path):** `screen_pwroff.sh` kills the programs,
  remounts `/` read-only and then drives **GPIO 111 low ("Set
  write-protect : GPIOD[15]")**. The 1X's script is 101 bytes and
  does neither.

## Pins that differ from the 1X

From `/sys/class/gpio` (exported pins) and `/app/pinconf.sh`
against `/app/pinconf_r2.sh` (both scripts are on the 2X; the r2 one
carries the names). On r1 the block D16-D25 of the r2 board sits 14
pins higher:

| Signal (name from `pinconf_r2.sh`) | r2 / 1X | r1 / this 2X |
|---|---|---|
| `PSU_O1_FAN_CTRL` | D16 = 112 | D30 = 126 |
| `PSU_O2_FAN_CTRL` | D17 = 113 | D31 = 127 |
| `PSU_O1_FAN_LOCK` | D18 = 114 | E0 = 128 |
| `PSU_O2_FAN_LOCK` | D19 = 115 | E1 = 129 |
| `SoC_I/F_A` (power board to SoC, the button) | D20 = 116 | E2 = 130 |
| `EX_FIL_SEN1` | D24 = 120 | E6 = 134 |
| `EX_FIL_SEN2` | D25 = 121 | E7 = 135 |

- `powerkeyd` runs as `powerkeyd 130 158 20 1 1 3000`: the button
  line is **130**, the answer line is still **158**, and the delay
  before the answer is 3000 ms (r2: 1000).
- (our reading) on r2 these pins moved because D30/D31 became eMMC
  lines (`pinconf_r2.sh` comments D30 and D31 as "eMMC").
- **GPIO 69** ("nozzle voltage on" on the 1X) is not among the
  exported pins here, and 112, 114, 116, 120, 121 are not either.
  Everything else exported is the same set as on the 1X.
- Not checked yet: the motor enables, the fan enables, the nozzle
  I2C buses and which pin (if any) powers them on this board.

## Other differences seen

- The same programs run: `UIManager`, `appBrowser` on
  `/app/SVN_GUI/home.html`, the motion program
  `/marvell_lspsdk_3dp_granite2-debug_stripped.elf`, `powerkeyd`,
  `lighttpd`, `mjpg_streamer` on port 8080. The binaries differ from
  the 1X's (different checksums; `upc_6270.ko` is 56 bytes longer).
- `/boot` holds five device trees. The one in use is
  `mv6270-toc.dtb`; **`mv6270-Prime-r2.dtb` is byte for byte the 1X's
  `mv6270-1X.dtb`** (same md5), so the 1X board is the "Prime r2"
  board under another name.
- USB: the same webcam (`0c45:6341`), audio (`0572:143b`) and Wi-Fi
  (`1286:2040`) devices as the 1X, on other hub ports.
- I2C adapters `i2c-0` to `i2c-5`, as on the 1X.

## What this means for a Klipper install (our reading)

- The 1X method (our files in `/userdata/klipper`, a boot hook there)
  has no home on this machine: there is no eMMC, and the NAND root
  has 42 MB free.
- The DP200 family's lessons apply instead: NAND writes are the
  owner's call, each one; the U-Boot blocks and environment are never
  written.
- The 1X firmware files and config cannot be used as they are: at
  least the PSU fan pins, the power button line and the filament
  sensors are on other pins.
