# 88PA6270 (2X/1X/7X) vs 88PA6170 (DP200): what carried over (2026-11-01)

**Sources:**
- the 7X firmware's device tree `mv6270-H.dtb` (Linux 4.2.8);
- strings from the decompressed 6270 and 6170 vendor kernels;
- our 6170 device tree and register notes (common/upc_hw.h,
  vendor_hwtables.txt).

Marvell's public GitHub only has the WTP/TIM boot tool for the 6270
(kernel/marvell_github.md).

## Same block, same address

| Block | 88PA6170 (ours) | 88PA6270 DT | Note |
|---|---|---|---|
| Stepper engines | `smot` 0xf8150000, 0x5000 | `stepper-mod` 0xf8150000-0xf8155000, "mrvl,stepper-mod-b0" | 6 modules on both |
| PWM | `pwm` 0xf9304000, 0x2100 | `dec-pwm` 0xf9304000-0xf9306000 | |
| ADC | ADC_BASE 0xf930a000; run word 0x7770c006, cfg 0x00244d01 | `dec-adc` 0xf930a000; `saradc` 0x7770c002, `adc_control` 0x01144d01 | same field layout |
| Encoder / sensor | DEC_SENSOR_BASE 0xf9301000 | `dec-sensor` 0xf9301000 | |
| Timers | 0xf8020000 | `timer-ips` 0xf8020000 (disabled there) | |
| SoC temperature | 0xf80f0000 | `tsen` 0xf80f0000 | |
| Engine interrupt controller | 0xf9300100 | 0xf9300100 ("cortex-a15-sic") | |
| NAND controller | 0xf9082000, vendor driver `mv61x0_nand` | 0xd4283000, compatible `"mrvl, mv61x0_nand"` | **same driver**, moved |

**NAND, in detail.** Both vendor kernels share:
- the driver parameters `enable_ecc`, `use_bbt`, `wait_on_load`,
  `trace_mode`;
- the "programz" OOB marker;
- the `Bbt`/`tbB` BBT signatures;
- the NDSR messages.

So our bch_v1 read/write path, the vendor BBT handling and patch 0010 should
apply to the 6270's NAND boards (2X Prime_r1) with a new address. They
also share the early-UNCERR issue to watch for.

## Moved or changed

- **UPC cores:** 0xf9200000/0xf9210000 on the 6170, 0xf9800000/0xf9810000
  on the 6270. The 6270 has ITCM 0x8000 and a shared DTCM at 0xf9880000
  (0x40000). Same driver idea (`upc`, `upc_6270.ko`), new memory map.
- **New on the 6270:** DC motor blocks (`mrvl,mv62x0-dcmotor-reg-b0`,
  0xf8140000-0xf8146000).
- **CPU and SoC infrastructure, replaced** (PXA/Armada-style blocks at
  0xd4xxxxxx):
  - Cortex-A53 cores;
  - pxa UARTs and I2C;
  - pegmatite SDHCI;
  - an snps,dwmac at 0xd0700000;
  - USB3;
  - PCIe;
  - a GIC at 0xd1d01000.
  None of our 6170 drivers for these carry over. Mainline already has
  drivers for most of these block types (pxa-uart, pxa-i2c, dwmac,
  sdhci-pxa), which makes a mainline port of the 6270 easier than the 6170
  was.

## So

- **For the DP200:** this confirms our own measurements but adds no new 6170
  fact.
  - The ADC, PWM and stepper addresses agree with what we probed.
  - The 6270 names (`dec-*`, `stepper-mod-b0`) label blocks we already use.
- **For the 2X/1X/7X:** the print-engine side should carry over almost
  unchanged:
  - the stepper, PWM, ADC and sensor registers;
  - our UPC/Klipper work, after the new UPC address;
  - the NAND driver.
  The CPU side needs new mainline support, but mostly from existing
  mainline drivers.
