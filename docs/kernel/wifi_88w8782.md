# Wi-Fi under mainline: Marvell 88W8782 (USB 1286:2040)

Offline findings, 2026-10-29. Inputs: the stock rootfs dumps
(`backup/171114_4_open`, `backup/Sindoh_raw_dump`) and Linux 6.18.59.

## What the stock printer runs

| Item | Value |
|---|---|
| Chip | Marvell 88W8782, rev B0, RF878X, 1x1 802.11n, USB 2.0. Port 1 of the on-board hub 1a40:0101, behind ehci.1 |
| USB ID | 1286:2040, the same before and after the firmware download |
| Driver | Marvell SDK `mlan.ko` + `usb8xxx.ko` from `/lib/modules/8782/`, tagged "M2614459-GPL-(FP69)". It supports USB8782 and USB8797 and kernels up to 3.4 |
| SDK ID table | 1286:2040 (8782), 1286:2043 / 1286:2044 (8797 boot / firmware), 045e:02cf (8797, Microsoft-branded) |
| Firmware | `/lib/firmware/mrvl/usb8782_uapsta.bin`, 253,996 bytes, md5 `6c11556fd22089c7f084613549a721e2`, "w8782-B0, RF878X, FP69, 14.69.12.p50" |
| Userspace | `wpa_supplicant` and `udhcpc` on `mlan0` (pid files in `/var/run`). Also uAP scripts (`uap_start.sh`, `uaputl`) for access-point mode |

## Mainline

- **No driver claims 1286:2040.** mwifiex USB lists 8766 (0x2041/0x2042),
  8797 (0x2043/0x2044), 8801 (0x2049/0x204a) and 8997 (0x2052/0x204e);
  libertas lists 8388/8682. linux-firmware has no `usb8782` image.
- **mwifiex is the right base.** It descends from the same Marvell SDK. It
  already drives the 8797, which this very SDK build drives alongside the
  8782, and it speaks the same uAP/STA firmware API generation (FP68/FP69).
  The 8782 is the 1x1 sibling of the 8766.
- **The patch would need three things:**
  1. Add PID 0x2040 to `mwifiex_usb_table` with the firmware name
     `mrvl/usb8782_uapsta.bin`, handled like the 8766 (`usb.c` probe switch
     and `mwifiex_register_dev`).
  2. A boot-state decision for a single-ID device. mwifiex picks
     download vs ready from the product ID, and expects a re-enumeration
     with a second ID after the download. The SDK's `woal_usb_probe` sets
     boot state only for the 8797 IDs and leaves it undecided for 0x2040.
     Likely candidates are `bcdDevice` (the boot2 version) or the endpoint
     layout. Image 6b prints both for every USB device; compare a cold
     boot (boot ROM) with stock's running firmware (stock:
     `cat /sys/bus/usb/devices/1-1.1/bcdDevice`, path per `lsusb -t`).
  3. Possibly small command/TLV differences found during bring-up (scan,
     associate). This is the risky part, but it can be tested
     incrementally: firmware download → `mlan0`/`wlan0` appears → scan.
- **Kernel config needed:** `CFG80211`, `MWIFIEX`, `MWIFIEX_USB`, `FW_LOADER`,
  and the firmware in the initramfs (`/lib/firmware/mrvl/`, +~250 KB). No
  mac80211; mwifiex is a cfg80211 full-MAC driver.
- **Userspace needed:** static `wpa_supplicant` (nl80211 needs libnl or
  libnl-tiny; internal TLS for WPA2-PSK) and `iw` for testing. The network
  credentials are in the stock printer's config.
- **Licensing:** the firmware is a Marvell binary from the printer's own
  rootfs. Keep it out of the public repo; `build.sh` can copy it from the
  local dump.

## Hardware facts (boot 6) and the patch

- On a cold boot under mainline the 8782 shows bcdDevice 0x3119 and three
  bulk endpoints each way (01/02/03 out, 81/82/83 in). The stock dmesg also
  shows "VID/PID = 1286/2040, Boot2 version = 3119" at probe, and **no
  re-enumeration** after the firmware download: the SDK continues on the
  same USB device.
- `kernel/m1/patches/0004-mwifiex-usb-add-88w8782.patch`:
  - adds 1286:2040 to the ID table;
  - probe starts in firmware-download state, as for the PID_1 IDs;
  - after a successful download, the boot state is set to ready and the
    driver waits 100 ms, then carries on in place (other chips return here
    and wait for the re-enumerated PID_2 device);
  - 2K transmit buffers, the legacy scan command (`ext_scan = false`) and
    the firmware name `mrvl/usb8782_uapsta.bin`.
- Image `a15d015d…` (m1.uimg, 1,863,877 bytes) carries it, and its `/init`
  runs `iw dev mlan0 scan passive`.

**Verdict:** realistic, at medium risk. Next step: boot image 6b, read the
8782's `bcdDevice` and endpoints in boot-ROM state, and compare with
stock. Then write the mwifiex patch and add a CFG80211 + MWIFIEX_USB build
to watch the firmware download and interface creation.
